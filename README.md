# Rawdinal

Rawdinal is an experimental native Rust decoder for observed Sigma Merrill and Quattro X3F layouts. Supported sensor layouts are:

| Observed cameras | X3F versions | RAW type / TRUE format | CAMF type | Encoded layer dimensions (bottom, middle, top) |
| --- | --- | --- | --- | --- |
| DP1/DP2/DP3 Merrill, SD1 Merrill | 2.3, 3.0, 3.1 | 1 / `0x1e` | 4 | 4928x3264 on all layers |
| dp0/dp2/dp3 Quattro | 4.1 | 1 / `0x23` | 5 | 2944x1836, 2944x1836, 6272x3672 |
| sd Quattro | 4.2 | 1 / `0x25` | 5 | 2944x1888, 2944x1888, 5888x3776 |
| sd Quattro H | 4.2 | 1 / `0x27` | 5 | 3328x2240, 3328x2240, 6656x4480 |

Support is restricted to these observed version/format/geometry combinations, rather than every mode or firmware of each camera. `SensorFormat::SdQuattro` covers both sd Quattro formats; callers must use each decoded plane's dimensions. The experimental linear-sRGB renderer is limited to the original sd Quattro.

The original 164-file validation corpus (59 Merrill, 100 dp3 Quattro, and 5 sd Quattro files) and 11 additional supported files from raw.pixls.us agree byte-for-byte with fixtures generated by pinned Kalpanika X3F Tools for decompressed CAMF and every physical-plane sample; this is not universal ground truth. Sensor planes preserve their full encoded dimensions; the dp Quattro top layer is wider than its nominal image width, and crop interpretation remains future calibration or adapter work.

The raw.pixls.us corpus also contains six unsupported legacy files: DP1, DP1s, SD9, SD10, SD14 and SD15. Tests check that decoding rejects them. In particular, legacy RAW type 3 / TRUE `0x1e` is distinct from Merrill RAW type 1 / TRUE `0x1e`. Rawdinal is not a general Foveon converter and does not provide calibrated rendering for Merrill, dp Quattro or sd Quattro H cameras.

## Build and test

Rawdinal requires Rust 1.85 or newer and currently supports native Linux builds.

```sh
cargo test --workspace --locked
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --parallel
ctest --test-dir build --output-on-failure
```

The CMake build exposes the `rawdinal` target when included with `add_subdirectory`. Standalone builds install `include/rawdinal.h` with the static library by default; embedded builds can opt in with `RAWDINAL_INSTALL=ON`.

## Independent decoder references

The ignored byte-for-byte decoder test compares unprocessed physical sensor layers, not SPP TIFF output. Its agreement is with fixtures generated by the pinned X3F Tools decoder, not universal ground truth. Fetch the immutable `Kalpanika/x3f` commit `e8b48cac0de92c1f0e694ac87a9e0fc31d65cbe3` as a tarball or checkout, then compile the dumper separately from Rawdinal's build systems:

```sh
git clone https://github.com/Kalpanika/x3f.git x3f
git -C x3f checkout --detach e8b48cac0de92c1f0e694ac87a9e0fc31d65cbe3
test "$(git -C x3f rev-parse HEAD)" = e8b48cac0de92c1f0e694ac87a9e0fc31d65cbe3
test -z "$(git -C x3f status --porcelain)"
cc -std=c11 -Wall -Wextra -Werror -I x3f/src \
  -DX3F_REFERENCE_DECODER='"Kalpanika/x3f@e8b48cac0de92c1f0e694ac87a9e0fc31d65cbe3"' \
  -c tests/reference_dump.c -o reference_dump.o
cc reference_dump.o x3f/src/x3f_io.c x3f/src/x3f_printf.c -o reference_dump
mkdir reference
./reference_dump INPUT.x3f reference
X3F_SAMPLE=INPUT.x3f X3F_REFERENCE_DIR=reference \
  cargo test -p rawdinal --test decoding sample_matches_independent_reference_byte_for_byte -- --ignored --exact
X3F_SAMPLE_DIR=.opencode/x3f-samples X3F_REFERENCE_DIR=.opencode/x3f-references \
  cargo test -p rawdinal --test decoding corpus_matches_independent_references_byte_for_byte -- --ignored --exact
```

Cargo and CMake do not build the external X3F Tools source. The dumper creates `reference.txt`, `calibration.bin`, and one little-endian `layer-N.u16le` file for each physical layer; the test requires all of them. Output creation is exclusive: after a failed or partial dump, replace the output directory with a fresh empty directory before retrying.

For the 17-file raw.pixls.us Sigma corpus, generate references for the 11 supported files with the same dumper. Preserve the model directories and use the input filename without its extension as the reference directory: `sd Quattro H/SDIM0061.X3F` maps to `sd Quattro H/SDIM0061/`. The six unsupported files require only their original X3Fs. Sample files and independent dumps are external fixtures, not bundled with the library; the downloaded `manifest.json` records source URLs, SHA-256 hashes and per-file licenses.

```sh
X3F_PIXLS_SAMPLE_DIR=.opencode/x3f-samples/raw-pixls-us \
X3F_PIXLS_REFERENCE_DIR=.opencode/x3f-references/raw-pixls-us \
  cargo test --release --locked -p rawdinal --test decoding \
  pixls_corpus_matches_independent_references_and_rejects_unsupported_formats -- --ignored --exact
```

## C API ownership

`rawdinal_preview` returns storage borrowed from the input buffer. `rawdinal_decode` returns an owned opaque image handle whose EXIF pointer remains valid until `rawdinal_free`. `rawdinal_decode_with_clipping_v1` additionally retains output and bottom/middle/top native masks borrowed through `rawdinal_get_clipping_v1` until `rawdinal_free`; threshold flags identify estimated encoded maxima, not calibrated physical saturation. `rawdinal_copy_rgba` copies unbounded linear-sRGB RGBA values into caller-owned storage. `rawdinal_sensor_v1_decode` owns decoded physical planes plus copied EXIF and decompressed CAMF; its getters borrow those buffers until `rawdinal_sensor_v1_free`.
